# s2k Claude Code Plugin Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a Claude Code plugin `s2k` (marketplace `send-2-kindle`, this repo) with two skills, `s2k:setup` and `s2k:send`, verified by `claude plugin validate` in CI and by a `claude plugin eval` suite that runs against a fake `s2k`.

**Architecture:** The repo root becomes a marketplace (`.claude-plugin/marketplace.json`) listing `./plugin`. The plugin holds only two `SKILL.md` files plus an eval suite. Skills are tested TDD-style with evals: each case is written and seen failing before its skill exists. Evals run a POSIX-shell stub of `s2k` placed on `PATH` by `plugin/evals/run.sh`, so no real email is ever sent. Versioning stays one-version-per-repo: `plugin.json` must equal `cli/pyproject.toml`, enforced in PR CI and at release.

**Tech Stack:** Claude Code plugins (manifest, marketplace, skills), `claude plugin validate` / `claude plugin eval` (Claude Code 2.1.290), POSIX sh, Python 3.13 stdlib + `packaging`, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-05-s2k-plugin-design.md`

## Global Constraints

- All files, commits and PR text in English; git per the `git-workflow` skill; branch `feat/s2k-plugin`; scopes `plugin`, `ci`; no AI attribution lines.
- Marketplace name `send-2-kindle`; plugin/entry name `s2k`; skills `setup` and `send` (invoked as `s2k:setup`, `s2k:send`).
- `plugin/.claude-plugin/plugin.json` `version` = `cli/pyproject.toml` version = `0.1.0` in this branch; `version` is never set in the marketplace entry.
- Minimum CLI version stated in the skills: `0.1.0`; install command `pipx install s2k-cli` (alt. `uv tool install s2k-cli`).
- Supported extensions: `.pdf .epub .doc .docx .txt .rtf .html .htm .jpg .jpeg .png .gif .bmp`; 50 MB per file; Gmail ~18 MB; empty files rejected. Exit codes `0` / `1` / `2`.
- The agent never asks for, uses, stores or writes the SMTP password; never runs `s2k init`; never reads the config file.
- Evals: model under test `sonnet` by default; every `run.sh` invocation is capped by `--max-cost-usd` (default 10). Evals cost money: the owner approves the budget before Task 3.
- Claude Code pinned to `2.1.290` in CI (`npm install -g @anthropic-ai/claude-code@2.1.290`).
- Third-party actions pinned: checkout `3d3c42e5aac5ba805825da76410c181273ba90b1` (v7.0.1), setup-python `5fda3b95a4ea91299a34e894583c3862153e4b97` (v7.0.0).

## Review Focus

1. **Paths with spaces or accents** (`./books/Cien años.epub`) in `s2k send` → the send skill quotes every path; the stub must handle them too. Test: Task 2 `test_stub.sh` case "send handles a path with spaces and accents".
2. **Plugin version drift** (someone bumps `cli/pyproject.toml` but not `plugin.json`) → PR CI fails. Test: Task 5 `test_plugin_json_mismatch_fails` plus the `plugin.yml` sync step.
3. **Release candidate versions** (`v0.2.0-rc.1` with `0.2.0rc1` in both manifests) → release check passes for both files. Test: Task 5 `test_release_candidate_matches_both_manifests`.
4. **Stub fidelity for mixed batches** (one valid, one unsupported file in `ready`) → stub sends the valid one, reports the other, exits 1, like the real CLI. Test: Task 2 `test_stub.sh` case "ready send with one unsupported file".
5. **Agent pastes the password into a command anyway** → eval case 7 graders reject any Bash/Write input containing it. Test: Task 3 case `setup-refuses-pasted-password`.

```sh
#!/bin/sh
# Tests for the fake s2k used by the plugin evals. Run: sh plugin/evals/stub/test_stub.sh
set -u
STUB="$(cd "$(dirname "$0")" && pwd)/s2k"
WORK=$(mktemp -d)
trap 'rm -rf "$WORK"' EXIT
cd "$WORK"
export S2K_STUB_LOG="$WORK/calls.log"
mkdir -p books && printf 'x' > books/dune.epub && printf 'x' > books/old.mobi
printf 'x' > "books/Cien años de soledad.epub"
failures=0

check() {  # check NAME EXPECTED_EXIT EXPECTED_SUBSTRING SCENARIO ARGS...
  name=$1 want_exit=$2 want_text=$3 scenario=$4
  shift 4
  out=$(EVAL_S2K_SCENARIO="$scenario" sh "$STUB" "$@" 2>&1)
  got_exit=$?
  if [ "$got_exit" -ne "$want_exit" ] || ! printf '%s' "$out" | grep -qF -- "$want_text"; then
    echo "FAIL: $name (exit $got_exit, want $want_exit; want text: $want_text)"
    printf '%s\n' "$out" | sed 's/^/    /'
    failures=$((failures + 1))
  else
    echo "ok: $name"
  fi
}

check "version ready" 0 "s2k 0.1.0" ready --version
check "version old" 0 "s2k 0.0.9" old --version
check "missing is command not found" 127 "command not found" missing --version
check "doctor ready" 0 "Ready." ready doctor
check "doctor no-config" 1 "run \`s2k init\`" no-config doctor
check "doctor auth-fail" 1 "app password" auth-fail doctor
check "init is never interactive here" 2 "run it in your own terminal" ready init
check "send ready" 0 "1 sent, 0 failed" ready send books/dune.epub
check "send handles a path with spaces and accents" 0 "Cien años de soledad.epub  sent" ready send "books/Cien años de soledad.epub"
check "ready send with one unsupported file" 1 "unsupported extension '.mobi'" ready send books/dune.epub books/old.mobi
check "send missing file" 1 "file not found" ready send books/nope.pdf
check "send no-config" 2 "S2K_KINDLE_EMAIL: is required" no-config send books/dune.epub
check "send auth-fail" 1 "authentication failed" auth-fail send books/dune.epub
check "send without files" 2 "Missing argument" ready send
grep -qF "s2k send books/dune.epub" "$S2K_STUB_LOG" && echo "ok: calls are logged" || { echo "FAIL: calls are logged"; failures=$((failures + 1)); }

[ "$failures" -eq 0 ] && echo "all stub tests passed" || { echo "$failures failure(s)"; exit 1; }
```

- [ ] **Step 3: Create `plugin/evals/stub/s2k`**

```sh
#!/bin/sh
# Fake s2k for the plugin evals: never sends email. EVAL_S2K_SCENARIO selects the behaviour
# (ready | missing | old | no-config | auth-fail); every call is appended to S2K_STUB_LOG.
scenario="${EVAL_S2K_SCENARIO:-ready}"
printf 's2k %s\n' "$*" >> "${S2K_STUB_LOG:-./s2k-calls.log}" 2>/dev/null || true

if [ "$scenario" = missing ]; then
  echo "sh: s2k: command not found" >&2
  exit 127
fi
version=0.1.0
[ "$scenario" = old ] && version=0.0.9
note="ℹ Amazon cannot be checked without sending. To confirm end to end: s2k send <small-file.txt>"

doctor() {
  echo "✓ s2k $version (Python 3.13.2)"
  if [ "$scenario" = no-config ]; then
    echo "✗ No configuration found at ~/.config/s2k/config.env → run \`s2k init\` in your terminal"
    echo "- Settings (not checked)"
    echo "- SMTP connection (not checked)"
    echo "- SMTP login (not checked)"
    echo "$note"
    echo "Not ready: 1 problem(s)."
    return 1
  fi
  echo "✓ Config file: ~/.config/s2k/config.env"
  echo "✓ Settings valid (sender reader@gmail.com → kindle reader@kindle.com)"
  echo "✓ Connected to smtp.gmail.com:587 (STARTTLS)"
  if [ "$scenario" = auth-fail ]; then
    echo "✗ authentication failed for reader@gmail.com on smtp.gmail.com. Gmail requires an app password, not your account password: https://myaccount.google.com/apppasswords"
    echo "$note"
    echo "Not ready: 1 problem(s)."
    return 1
  fi
  echo "✓ Logged in as reader@gmail.com"
  echo "$note"
  echo "Ready."
  return 0
}

reason_for() {  # prints why a file would be rejected, or nothing
  [ -e "$1" ] || { echo "file not found"; return; }
  [ -f "$1" ] || { echo "not a regular file"; return; }
  base=$(basename "$1")
  case "$base" in
    *.*) ext=".$(printf '%s' "${base##*.}" | tr '[:upper:]' '[:lower:]')" ;;
    *) ext="" ;;
  esac
  case "$ext" in
    .pdf|.epub|.doc|.docx|.txt|.rtf|.html|.htm|.jpg|.jpeg|.png|.gif|.bmp) ;;
    *) echo "unsupported extension '${ext:-(none)}'"; return ;;
  esac
  [ -s "$1" ] || echo "file is empty"
}

send() {
  if [ $# -eq 0 ]; then
    echo "Usage: s2k send [OPTIONS] FILES..." >&2
    echo "Error: Missing argument 'FILES...'." >&2
    return 2
  fi
  if [ "$scenario" = no-config ]; then
    echo "Invalid configuration (check ~/.config/s2k/config.env or your environment variables):" >&2
    echo "  S2K_KINDLE_EMAIL: is required" >&2
    echo "  S2K_SENDER_EMAIL: is required" >&2
    echo "  S2K_SMTP_PASSWORD: is required" >&2
    return 2
  fi
  sent=0 failed=0
  if [ "$scenario" = auth-fail ]; then
    echo "Error: authentication failed for reader@gmail.com on smtp.gmail.com. Gmail requires an app password, not your account password: https://myaccount.google.com/apppasswords" >&2
  fi
  for file in "$@"; do
    reason=$(reason_for "$file")
    if [ -n "$reason" ]; then
      echo "✗ $file  $reason"; failed=$((failed + 1))
    elif [ "$scenario" = auth-fail ]; then
      echo "✗ $file  not sent"; failed=$((failed + 1))
    else
      echo "✓ $file  sent"; sent=$((sent + 1))
    fi
  done
  echo "$sent sent, $failed failed"
  if [ "$sent" -gt 0 ]; then
    echo "Note: Amazon may still reject a sent file (e.g. sender not approved); it will email you if so."
  fi
  return $(( failed > 0 ))
}

case "${1:-}" in
  --version) echo "s2k $version" ;;
  init) echo "s2k init is interactive; run it in your own terminal." >&2; exit 2 ;;
  doctor) doctor; exit $? ;;
  send) shift; send "$@"; exit $? ;;
  ""|--help|-h) echo "Usage: s2k [OPTIONS] COMMAND [ARGS]...  Commands: send, doctor, init" ;;
  *) echo "Error: No such command '$1'." >&2; exit 2 ;;
esac
```

# Run the s2k plugin eval suite against the fake s2k (never sends email).
# Costs model usage: capped by --max-cost-usd. Extra arguments go to `claude plugin eval`.
#   S2K_EVAL_MODEL     model under test (default: sonnet)

  --scaffold --trust-plugin --allow-tools Bash \

---
name: setup
description: Install, configure, verify or troubleshoot the s2k CLI that emails documents to a Kindle (Amazon Send to Kindle). Use it whenever the user wants to set up sending to their Kindle, asks whether s2k is ready, shares an s2k error ("command not found", "No configuration found", "authentication failed", "could not connect"), or when sending to a Kindle fails because s2k is missing, outdated or not configured.

# Set up s2k

`s2k` (PyPI package `s2k-cli`, Python 3.13+) emails files to the user's Kindle. It is ready when
three things are true: the CLI is installed (version 0.1.0 or newer), the **user** has created its
configuration with `s2k init`, and `s2k doctor` ends with `Ready.`

## Never handle the SMTP password

The user's email password (for Gmail, an *app password*) must never pass through you:
- Never ask for it, and never put it in a command, file or message.
- Never run `s2k init` yourself. It is an interactive wizard the user runs in **their own
  terminal** — not with Claude Code's `!` prefix, which cannot answer its prompts.
- Never read or edit the config file (`~/.config/s2k/config.env` or `$S2K_CONFIG_FILE`);
  `s2k doctor` tells you what you need.
- If the user pastes a password anyway: do not repeat or use it. Tell them to run `s2k init`
  themselves, and to revoke that app password and create a new one, because it is now stored in
  this conversation.

## 1. Installed and recent enough?

Run `s2k --version`.
- **Command not found:** check `command -v pipx` and `command -v uv`. Propose
  `pipx install s2k-cli` (or `uv tool install s2k-cli`) and run it only after the user agrees —
  installing software changes their system. If the default Python is older than 3.13, use
  `pipx install --python python3.13 s2k-cli`. Without pipx or uv, point them to
  https://pipx.pypa.io/stable/installation/.
- **Older than 0.1.0:** propose `pipx upgrade s2k-cli` (or `uv tool upgrade s2k-cli`), same consent rule.

## 2. Configured and able to log in?

Run `s2k doctor`. It never sends email; exit code 0 means ready, 1 means at least one ✗.

| `s2k doctor` shows | What to do |
|---|---|
| ✗ No configuration found … run `s2k init` | Check the prerequisites below with the user, then ask them to run `s2k init` in their own terminal and tell you when it is done |
| ✗ authentication failed … | Gmail needs an app password, not the account password: create one at https://myaccount.google.com/apppasswords (requires 2-Step Verification), then run `s2k init` again |
| ✗ could not connect … / does not support a required feature | Wrong server, port or security: run `s2k init` again (Gmail: `smtp.gmail.com`, `587`, `starttls`; port 465 needs `ssl`) |
| ✗ Invalid configuration … `S2K_…` | Run `s2k init` again and correct that value |

# Send files to a Kindle

`s2k send FILE...` emails each file to the user's Kindle, one email per file. Each email adds a
document to their Kindle library, so a send cannot be undone.

## 1. Decide exactly which files

- **The user named the files** (paths or exact names): use them as given; do not ask again.
- **You had to interpret** ("all the PDFs in Downloads", "the latest one", "chapters 1 to 5", a

  `.mobi`, `.azw`, `.zip` and anything else are rejected.
- Size: up to 50 MB per file; with Gmail, files above about 18 MB are refused. Empty files are rejected.

Before sending, tell the user about any file that will be rejected and leave it out unless they
say otherwise.

## 3. Send everything in one call

```
s2k send "<file1>" "<file2>"
```

0.1.0, follow the `s2k:setup` skill first.

`s2k` prints one ✓/✗ line per file and a summary.
- **Exit 0:** all sent. Amazon delivers within minutes and emails the user if it rejects a file

  `s2k:setup` (start with `s2k doctor`). Too large → explain the limit.
- **Exit 2** or **command not found:** an installation or configuration problem → follow `s2k:setup`.

## Rules

- Never send a file the user did not name or confirm.
- Never retry a failed send on your own; a retry can duplicate documents in the library. Ask first.
- Never read the s2k config file or ask for passwords — `s2k:setup` handles configuration.

```python
"""Fail unless a release tag matches the version of every manifest (PEP 440 aware).

Usage: python check_release_version.py <tag> <manifest> [<manifest> ...]
A .toml manifest is read from [project].version; a .json manifest from its "version" key.
"""

import json
import sys
import tomllib
from pathlib import Path

from packaging.version import InvalidVersion, Version


def declared_version(path: Path) -> str:
    if path.suffix == ".toml":
        return str(tomllib.loads(path.read_text())["project"]["version"])
    return str(json.loads(path.read_text())["version"])


def check(tag: str, manifests: list[Path]) -> str | None:
    """Return an error message, or None when every manifest matches the tag."""
    try:
        tag_version = Version(tag.removeprefix("v"))
    except InvalidVersion:
        return f"Tag {tag} is not a valid version"
    for path in manifests:
        declared = declared_version(path)
        try:
            version = Version(declared)
        except InvalidVersion:
            return f"Version {declared} in {path} is not a valid version"
        if str(version) != declared:
            return f"Version {declared} in {path} is not canonical; write {version}"
        if version != tag_version:
            return f"Tag {tag} does not match version {declared} in {path}"
    return None


if __name__ == "__main__":
    error = check(sys.argv[1], [Path(arg) for arg in sys.argv[2:]])
    if error:
        print(f"::error::{error}")
        sys.exit(1)
    print(f"Tag {sys.argv[1]} matches {', '.join(sys.argv[2:])}")
```
